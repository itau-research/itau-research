# A Shared-Meaning-State Architecture for Reality-Connected AI: The Composite Interface

**Author:** Genki Takatori (writing as "itau"), independent researcher, Japan
**Original paper:** May 1, 2026 — [【次世代AI】現実接続AI・ヒューマノイドAIにおける共有意味状態型アーキテクチャの設計論](https://note.com/arsenal_best/n/n1e36576147f8) (Japanese)
**This summary:** November 6, 2026. One page, written to be found, read, and cited.

---

## The problem: conversation as the main process

Today's AI interfaces run on the chat loop: input, interpretation, a tool call if needed, a reply, then waiting. That loop works for search, writing, and simple agent tasks, but it makes conversation the main process — and while the AI talks, the rest of what it should be doing stops, lags, or goes unintegrated: observing the environment, watching for danger, reading the user's state, controlling a body, investigating in the background, turning over unfinished tasks, sorting experience for learning, updating long-term plans. The paper names this the **conversation-as-main-process problem**. Its example is a home humanoid deep in philosophical conversation while a child stands on the edge of a sofa and a pot is on the stove: a conversation-bound system must interrupt the talk to check, weaken its monitoring to keep talking, check sequentially and react late, or fail to integrate the information and misjudge whether to intervene. A person talks while keeping a peripheral eye on the child. An AI should exceed that parallelism, not be denied it by the loop.

## The proposal: a composite interface

The alternative is a **composite interface**: one AI subject operating many cognitive, generative, and action routes in parallel — text and voice conversation, visual and audio recognition, expression, gaze and body control, environmental monitoring and danger detection, investigation, reasoning, code and document generation, autonomous learning, long-term memory update, safety audit, tool action, **silence**, and **interruption** — and arbitrating among them as a single system. Around the routes sit the mechanisms that make them one system rather than a bundle: attention allocation, a system-wide resource decision about what is foreground, what runs in the background, what is deferred and what stops (explicitly not the attention inside a Transformer); interruption judgment, weighing the value of continuing the foreground task against the urgency of background events, the user's state, environmental risk, long-term goals, and unfinished debts in the action accounting; state synchronization; foreground output control; evaluation of action outcomes; and continual learning. A coordinator integrates the routes — synchronizing their states, setting priorities, detecting contradictions, judging interruptions, deciding what the user sees. It is not a router; it manages the whole system's attention and meaning.

## Meaning integration, not model integration

The core is the **shared meaning state**. The routes must semantically share the current purpose, the user's intent, the conversation context, the environment's state, the danger level, priorities, attention allocation, unfinished tasks, long-term goals, the body's state, which experiences are to be learned from, interruption conditions, and output-suppression conditions. Running several models or tools in parallel without that sharing yields only what the paper calls a colony-type AI — separate individuals cooperating with no shared nervous system. The composite interface aims at a multicellular AI, whose routes are organs of one body. Nor must everything live in a single giant model: several specialized models are acceptable, often more rational — the condition is that each route reflect the shared state in its own action judgments, not merely read it as data. Two consequences follow. Silence is redefined as an action: foreground output stops while monitoring, deliberation, memory updating, and readiness to interrupt continue. And safety is internal to the design: an independent safety-audit route that must not be subordinate to the conversation route, and per-route authority — conversation comparatively free, body control tightly constrained, external API calls requiring confirmation, financial transactions requiring human approval, emergency safety action granted limited autonomy.

## How it would be checked

Evaluation changes with the architecture. Beyond single-task scores, the paper lists parallel operation capacity, shared-state synchronization accuracy, attention-allocation performance, interruption-judgment performance, background-task usefulness, real-time responsiveness, cross-route consistency, and continual-learning efficiency — and proposes benchmarks to match: a Parallel Cognition Benchmark, a Shared State Synchronization Test, an Interruption Appropriateness Test, a Silence Activity Test, a Cross-Route Consistency Test, and a Real-World Response Test.

## What would show this design is wrong or unnecessary

The paper's claims cut both ways, and each negation is a failure mode. If a conventional chat loop with subordinate tool use matches a composite interface on the paper's own benchmarks — holding a conversation while detecting danger, responding to real-world change without delay or degradation — then the single loop was sufficient and the conversation-as-main-process problem is not the binding constraint claimed. If parallel routes with no shared meaning state — a colony of connected models — show no cross-route contradiction and pass the synchronization and consistency tests, then semantic sharing is not the requirement: mere parallelism was enough. And by the paper's own condition, a system whose routes read the shared state without letting it change their judgments — the vision route sees the child on the sofa, the conversation route does not react — has not achieved the design at all. The paper also names its practical obstacles: synchronized multimodal training data close to a full record of daily life, per-route latency requirements, and state drift between routes.
